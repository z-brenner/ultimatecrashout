# Ultimate Crashout — architecture, debt, and plan

Living document. Status as of the first foundation PR.

## Architecture in one page

| Layer | Where | Notes |
| --- | --- | --- |
| Simulation | `src/game/engine.ts` (`CombatGame`) | Fixed 60 Hz step, seeded RNG, Melee-style physics (wavedash, L-cancel, SDI, techs, ledges, clank). Pure TypeScript, no DOM. |
| Fighter data | `fighters/<id>/fighter.json` → `scripts/fighter_packs.mjs` → `src/game/generated/openFighterRegistry.ts` → `openRoster.ts` | Movement in Melee units; 13 normals generated by `fighterBuilders.ts`, overridable per pack via `gameplay.attacks`. |
| Fighter visuals | `fighters/<id>/render.json` → atlas builders → `public/assets/characters/open/<id>/00/<slot>.webp` | 50 animation slots, 192 px cells, 8 columns. 2D from sprite strips/sheets; 3D pre-rendered offline in Blender. Runtime is a 2D canvas. |
| Stages | `stages/<id>/stage.json` → `scripts/stage_packs.mjs` → `openStageRegistry.ts` | Static geometry + four images; optional GLB scene rendered with Three.js, falling back to 2D. |
| Rendering | `src/game/render.ts`, `effects.ts`, `threeStageRenderer.ts` | Canvas 2D fighters/effects over a 2D or WebGL stage. F9 draws the engine's live hitboxes. |
| UI | `src/ui/ui.ts` (string templates), `src/styles.css` | Screens are registry-driven: new ready packs appear on select screens automatically. |
| Input | `src/game/input.ts`, `gamepad.ts`, `src/ui/gamepadNavigation.ts` | Rebindable keyboard + Gamepad API with hot-plug and per-player bindings. |
| Tests | Vitest (`npm test`, 350+ unit/integration), Playwright (`npm run test:e2e`, real browser) | `npm run validate:public` is the full pre-PR gate. |

## Done in the foundation PR

- Per-fighter move authoring: frame data, knockback, authored hitbox chains,
  throws, jump count, shield, traction, air acceleration; validated with exact
  error paths and documented in `fighters/README.md`.
- In-match hitbox/hurtbox overlay (F9 or `?hitboxes=1`).
- 2D fighter builds from a fresh clone: no zsh, no private vault; drop PNG
  strips named after slots, missing slots fall back automatically.
- **Buckle**: original, CC0, all 50 animations, custom moves — the first
  production-ready fighter.
- **Crash Course**: original CC0 stage; `stage:build -- <id>` derives the
  thumbnail and checksums.
- Roster follows pack `order` across 2D/3D; Random fighter pick.
- Rebrand with settings/controller storage migration and preserved upstream
  attribution.
- Playwright browser tests (menus, auto-discovery, full match flow, damage,
  overlay, stage select, virtual gamepad) plus a CI job.
- High-severity dependency advisories patched.

## Technical debt and limitations

Ordered by how much they constrain the goals.

1. **CI has never run on this repository.** GitHub reports no workflows or runs
   for `z-brenner/ultimatecrashout`; Actions appears disabled. All evidence so
   far is local. Enable Actions (Settings → Actions → General).
2. **Two players, hard-wired.** `PlayerSlot = 0 | 1` and fixed-length tuples run
   through the engine, input, CPU, HUD, and UI. Four-player matches are a broad
   refactor, not a setting.
3. **No online multiplayer exists.** The fixed timestep and seeded RNG are a
   good start for lockstep or rollback netcode, but there is no state
   save/restore, no input serialization, no transport, and cross-browser
   determinism is untested. Treat online play as a project, not a task.
4. **Move behavior still partly keyed on move names.** Landing lag is derived
   (`recovery × 0.42`, clamped 6–16), combo-starter knockback scaling applies to
   jab/up-tilt/down-tilt, and hitboxes have no per-bubble angle or knockback. Packs
   cannot yet author landing lag, auto-cancel windows, per-hitbox angles,
   armor, or intangibility frames.
5. **New special mechanics need engine code.** Packs pick from enumerated
   projectile kinds and movement types. That keeps content non-executable
   (a deliberate safety property) but limits "unique abilities".
6. **Animation timing is coarse.** Attack clips are stretched across
   startup+active+recovery (fps ignored), and each frame is re-grounded on its
   lowest opaque pixel. There are no per-frame pivots or event markers, so
   syncing a key pose to the first active frame is trial and error.
7. ~~Root-absolute asset URLs prevented sub-path deployment.~~ Fixed: runtime
   paths go through `publicAsset()` and the build is relative by default;
   browser tests run under a sub-path and reject any request outside it.
8. **The 14 legacy prototypes cannot be rebuilt from a clone**: their sources
   live in a private, git-ignored vault; 3D also needs Blender + zsh. Running
   `scripts/open_fighter_pipeline/build_atlases.mjs` without that vault would
   rewrite `openAnimationMetadata.ts` with fewer fighters.
9. **Dev server needs a restart after `fighter:build`**: fighter metadata is
   injected through Vite `define` at config time.
10. **Lab "Hitbox" checkbox is a placeholder** (empty overlay); use F9 in a match.
11. **Skins**: `SkinId` declares 00–03, but only 00 exists anywhere.
12. **UI code size**: `ui.ts` (~2.5k lines of HTML strings) and `styles.css`
    (~5.5k lines with a late identity override layer) are workable but brittle
    for a full visual redesign.
13. **Pre-existing layout nits at 1280×720**: the player-name input overlaps the
    fighter epithet; the home "Rules" tile clips its text.
14. **Audio is shared** by every fighter; packs cannot declare voices or SFX.
15. **`website/`** is the upstream project's marketing site (its domain, copy,
    and Open Graph art). Decide: rebrand it or delete it.
16. **Tooling**: `npm audit fix`/`npm install vitest@…` crash in npm's resolver
    ("edgesOut"); a moderate vitest advisory remains until the lockfile is
    regenerated.
17. **Placeholder art**: Buckle and Crash Course are procedural stand-ins,
    and the logo mark is still the inherited "fold" motif.
18. **Naming risk**: no trademark clearance for "Ultimate Crashout"; see
    `IP_AND_CONTENT_POLICY.md`.

## Plan

### Phase 2 — make creation fast and correct (next)

1. Enable Actions and get all four CI jobs green.
2. Pack-authorable move timing: `landingLag`, `autoCancel` windows,
   per-hitbox `angle`/`baseKnockback`/`knockbackGrowth`, `intangibleFrames`,
   `superArmor`. These are small engine changes with clear tests.
3. Animation events: optional per-slot `keyFrame` (the atlas frame that should
   land on the first active frame) so art and hitboxes line up by design.
4. Real Lab hitbox viewer: step any fighter's move frame by frame with the
   engine's own hitbox data.
5. ~~Base-path-safe asset URLs~~ (done). Next: a deploy workflow for one
   static host once GitHub Actions is enabled.
6. Hot reload of fighter metadata in `npm run dev` (virtual module instead of
   `define`).
7. Replace Buckle's procedural strips with hand-drawn art (same filenames, no
   code change) and commission the logo.

### Phase 3 — scale the game

1. Palette-swap skins at runtime (tint ramps), avoiding 4× atlases.
2. Stage hazards and moving platforms as audited, data-driven mechanics.
3. Per-fighter audio in the pack contract.
4. N-player refactor (tuples → arrays) as its own PR series, with the engine
   tests as the safety net.

### Phase 4 — online (speculative)

Only after deterministic replays are proven: add state snapshot/restore,
replay files, a cross-browser determinism test, then rollback netcode over
WebRTC data channels with a small signaling service. Expect this to cost more
than everything above combined. Do not advertise online play before it is
tested over real networks.
